# viewer entrys 子树入口：渲染指定路径下的状态

viewer 原只能渲染整个 state 顶层。本决策引入 `entrys` 属性（String，attribute `entrys`，默认空）：空 = 渲染整个 state（既有行为不变）；逗号分割多个状态路径（单路径复用 `splitPath` 语法：点分隔、`a\.b` 转义、数组下标 `servers.0`），如 `entrys="orders.1,user.name"`，各入口子树**按声明序平铺在顶层**（单入口即其特例）。行 `data-path` 恒为绝对路径。

**技术基座——子树节点 path 保持绝对路径**（含入口前缀，如 `user.address.city`）。entrys 只改 `_buildTree` 的入口与「深度类」判定；watch 路径匹配、`_getSchemaByPath` schema 查询、`isComputed` 判定、编辑写回（`parent[key]=value`）、删除、`data-path` 全部零改动复用。

唯一例外是 `_getNodeByPath`（从树顶层逐段下钻的路径匹配器）：隐式根下树顶层从各入口子级起、不含入口段，绝对路径第一段在树内匹配不到——须命中某入口前缀则剥离后下钻（path 恰为入口路径时返回 null，入口行本身不渲染）。它是委托编辑（edit 常驻写回）、click-edit 状态机定位、watch 冻结判定的共同依赖，漏改则三条链在入口子树内静默失效。`_updateTreeNode`/`_removeTreeNode` 自行做全等路径比对、不经此函数，天然正确。

各项语义：

- **隐式根**：入口指向容器（对象/数组/markRaw）时渲染其**子节点**，入口行不出现——「只渲染该路径下的所有」的字面义。渲染入口行作为根分组的方案被否：多一层无意义包裹，且单/多入口行为分叉。
- **叶子单行**：入口指向原始值（含 null）时渲染单行（key = 路径末段，schema label/help/icon 照常按绝对路径生效）。「该路径之下」无内容，单行是自然退化；视为无效不可取（合法路径报错）。
- **无效路径提示态**：**任一**入口路径不存在（含中途断链）即整体渲染 `.loading` 风格提示「entrys 路径不存在: {无效清单}」+ `console.warn`，**不回落全树、不部分渲染**——掩盖配置错误违背「只渲染指定路径」契约。
- **root-bg 随入口移动**：`root-group` 判定 =「某入口的直接子级且有子节点」；entrys 为空时退化为绝对根顶层（`path.length === 1`），与既有行为一致。root-bg 的意图是「顶层分组视觉分区」，入口子树即新顶层。grid 线基于可见行几何，天然不受影响。
- **expandDepth 各入口重计**：每入口直接子级 depth=0 起算（`_buildNodes(value, entryPath, 0)` 天然成立）。「进入该路径后重新展开 N 层」符合直觉，不同入口深度视觉行为一致。
- **watch 三路分流**：① operate.path 在**全部**入口子树外 → 跳过树更新（前缀过滤，避免无谓空转）；② operate.path ⪯ 某入口路径（入口自身或其祖先的 set/delete）→ 重建整棵入口树——入口路径消亡自动落入无效提示态，整体替换重建（**展开状态丢失**：旧子树节点与新值无对应，按 key 匹配保留展开的复杂度不值）；③ 某入口子树内 → 走既有 `_updateTreeNode`/`_removeTreeNode`。
- **entrys 属性变更** → `_buildTree()` 重建（与 expandDepth/showComputed 同类；同款展开丢失语义）。

## 多入口专属决策

- **平铺**：各入口子树按声明序直接并列在顶层，无入口行/分组标题——单入口是多入口的特例（一个入口的隐式根），语义统一。
- **逗号分割、空白容错**：`split(',')` 后逐段 trim、空段忽略；逗号本身不支持转义（key 含逗号极罕见，`splitPath` 转义仅覆盖路径内分隔符 `.`）。
- **嵌套/重复入口吞并**：位于其它入口子树内（或相等）的入口被自动移除（更广者吞并窄者）——否则同一 state 路径会渲染两行同 `data-path`，而 `_updateTreeNode`/`_removeTreeNode` 是「首个匹配即止」，第二份将静默陈旧。吞并让路径恒唯一，既有更新链零改动。

## 边缘语义（派生事实）

- 路径存在但容器为空（`{}`/`[]`）→ 该入口渲染空白，与全树模式下空 state 行为一致。
- 入口指向 computed 容器 → `_getStateByPath` 触发求值，渲染计算结果；markRaw 容器照常遍历。
- 删除入口单行叶子（allowDelete）→ delete operate.path 恰为入口路径 → 走分流②重建 → 提示态，语义自洽。
- 入口顶层节点的 Enter 编辑链到末项停止——与全树模式顶层行为一致，不引入特殊分支。
- 列宽测量基于 `_treeNodes`（即全部入口子树并集），自动按入口内容自适应。

考虑过的替代方案：节点 path 改相对路径——被否：watch/schema/isComputed/编辑/删除全链路需加前缀拼接，改动面大且易错；entry 作为独立 viewer 包装组件——被否：单组件多实例（不同 entrys）即可满足，无须新组件；嵌套入口双份渲染——被否：同 data-path 行使「首个匹配即止」的树更新链残留陈旧副本，吞并是更小正确解。
