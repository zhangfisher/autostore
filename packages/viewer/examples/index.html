state 为 docker run 命令行参数，按功能分组；每个配置项均使用 configurable() 声明 schema（label / group / widget / choices / 校验 / icon / 值装饰 prefix·suffix 等），全部 31 个图标经 icon-url 从 iconify 批量拉取（仅一次合并请求）；本 viewer 显式覆写 icon-url 为 material-symbols-light（material 命名图标 + 填充系画风，与内置线型系不同——覆写拉取源者自担风格差，ADR-0033）并设置 icon-modify="outline"：请求名自动追加 -outline 后缀（schema.icon 引用名不变），可用控制面板切换风格对比

各 widget 的编辑控件演示（需将控制面板「编辑模式」切到 click-edit 或 edit；Schema 显示默认生效，可勾选「禁用 Schema 显示」对比）：click-edit 下双击值或按住 1 秒进入编辑（按住期间松开/移开/再按下即取消），编辑即时生效写入状态（无确认/取消）；值无效时控件下方实时显示红色错误且暂不写入，修正后自动写入并隐藏；Enter 前进到下一个可编辑节点；编辑在所有节点上生效——所有对象/数组容器（plainObject、withConfigurable、collapsedContainer、各分组）双击或按住 1 秒即进入 JSON 整体编辑，configurable 容器同样正常渲染子节点；edit 模式下叶子成员常驻编辑控件，Enter 在控件间转移焦点

图标注册链演示（slot 自定义 > 内置 > icon-url 拉取）：① user/box 引用 slot 自定义图标 custom-user/custom-box；② 本 viewer 覆盖内置 object/array 图标（同心圆/圆角方块），树中所有对象与数组节点即刻换装；③ home/star/settings/lock 四个未知名渲染时攒批合并为一次 iconify 批量请求——默认源 lucide 与内置图标同属线型系，拉取注册时统一重写线宽，与相邻内置类型图标画风一致（ADR-0033）；④ this-icon-does-not-exist 命中 not_found 负缓存，回落类型图标。icon-modify 风格后缀（material 系变体名）演示见 Docker tab

schema.actions 节点动作演示（悬停行显示按钮组；动作渲染在 node-tools 内、位于内置删除工具之前，两组并存且有删除工具渲染时有细分隔线；动作不受「禁用 Schema 显示」门控，「节点动作」下拉（show-actions：0=隐藏 / 1=悬停显示（默认）/ 2=始终显示）是其唯一显隐开关）：① 计数器 —— 仅 label 的动作渲染为小文字按钮，仅 icon 的动作（restart_alt 经 icon-url 从 iconify 拉取）渲染为图标按钮；onClick 收到 value=当前状态值，ctx.update(v) 写回该路径，树即时刷新；② enable=false 渲染但置灰不可点，visible=false 完全不渲染，icon 与 label 都无的动作跳过渲染（console 有 warn）；③ 主题 —— dropdown 形态（items 含 "-" 分割线、菜单项带图标、caret 显示下拉箭头、syncMenu 选中后把该项回写到触发按钮），菜单项 onClick 以该项为 ctx.action；④ 状态 —— image 形态（url 渲染为图片按钮，点击写回）；⑤ 服务器 —— 容器节点同样支持 actions（重置整个对象）。每次点击同时派发 'action' 自定义事件（bubbles+composed 穿透 shadow、cancelable）：detail = { path, value, action }，path 与行 data-path 同源；勾选「拦截事件」后 preventDefault 拦截，onClick 不再执行

entrys 子树入口（与示例 1 同一 store 实例）：默认空 = 渲染整个 state；逗号分割多个状态路径（单路径 splitPath 语法：点分隔、支持数组下标与 a\.b 转义），如 entrys="orders.1,user.name"——各入口子树按声明序平铺在顶层：容器为隐式根（入口行不出现，expand-depth 各自重计），叶子渲染单行，行 data-path 恒为绝对路径；任一入口路径无效则整体显示提示态且不回落全树；位于其它入口子树内的入口被自动吞并（同路径行不重复）；root-bg 根级分组判定随入口移动（入口顶层分组行生效）；全部入口之外的 store 变更不重渲染，入口路径被删除或整体替换时自动重建（入口消亡落入提示态）

only-configurable 配置面板（ADR-0034）：启用后只渲染 store 的 configurable 项（store.configurabled），configManager.groups 有值时按组呈现。渲染顺序 = 默认区（未声明 group 的项，置顶裸排无标题条）→ 真实组（SchemaGroup 的 order 升序、缺省沉底按注册序；组标题条可点击折叠/展开，title ?? name + 组图标 + 项数徽章，横跨整行不参与两列网格与列宽测量）→ 高级选项虚拟组（置尾）。advanced:true 的项一律归入「高级选项」默认折叠——优先于 group 声明（遥测上报声明了 editor 组仍被收进高级组），空则不产出。容器配置项渲染自身行（网络代理），其嵌套的 configurable 子项归位其子级不平铺（bypass 非 configurable 子级作为值结构成员照常显示）；internalCache 非 configurable 不渲染。「云端同步」为另一个 store 在共享 ConfigManager 上注册的跨 store 空组——标题条照常渲染、他 store 项不混入。组折叠态跨树重建保留；编辑/删除/图标等既有能力照常生效（控制面板可切换编辑模式）；关闭开关回落整树渲染；下方输入框可叠加 entrys 交集过滤（入口为过滤器：路径无效仅 console.warn、交集空渲染空白）

多 store 配置面板：下方 viewer 绑定另一个 store（同一共享 ConfigManager）——组清单对两个 viewer 相同（组聚合跨 store 可见），但组内项各归各 store：「云端同步」组在此有实际配置项（上方渲染为空组），「网络/外观/编辑器」组在此为空组；两个面板各自编辑互不干扰，configManager 统一持久化（load/save 由 ConfigManager source 决定）

store：云端账户配置（sharedCm11）

独立的多 store 配置面板（ADR-0034）：两个 viewer 都以 only-configurable 属性常驻启用配置面板模式（无开关、无回落整树），绑定共享同一 ConfigManager（独立实例 sharedCm12，global:false 不接管全局键）的两个 store。组清单由 configManager.groups 跨 store 聚合，对两个面板完全相同；组内项各归各 store 的 configurabled，互不混入：「网络」组在两侧都有项但内容不同（store A 是代理/DNS，store B 是 STUN），「外观/编辑器/高级选项」只在 viewerA 有项，「云端同步」只在 viewerB 有项、在 viewerA 渲染为空标题条（默认区置顶裸排 → 真实组按 order 升序（网络 0 → 外观 1 → 云端同步 5，编辑器缺省沉底）→ 高级选项虚拟组置尾）。两面板各自编辑互不干扰，非 configurable 项（internalCache）不渲染

dark 属性强制暗色主题，缺省跟随系统 prefers-color-scheme：上方 viewer 声明 dark 恒为暗色，下方未声明（暗色系统下与上方一致，亮色系统下保持亮色）。暗色为独立调色板片段：dark 属性与系统媒体查询共用（border/hover 取比底色略亮的同级灰），原生控件与滚动条经 color-scheme 跟随组件自身主题而非页面。全局控制面板「暗色主题」开关可运行时切换全部 viewer（与其它控制项同规则：变更时会覆盖各 viewer 的声明值）
