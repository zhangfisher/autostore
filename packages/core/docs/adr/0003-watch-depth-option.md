# `watch` 的 `depth` 选项：以声明式深度钻取后代变更

## 背景

`store.watch("order", cb)` 仅在 `order` 被整体重新赋值时触发，对后代变更（如 `state.order.price = 200`）无感——因为 `order` 本身的引用并未改变。这在某些场景下不符合直觉：用户希望"监听 `order`"就包含其内部成员的变化。

fastevent 已提供通配符订阅，`watch("order.**", cb)` 可监听 `order` 的全部后代（且 `**` 含自身，见下）。但直接要求用户改用通配符有两个问题：

1. **`**` 含自身**这一行为并不广为人知（与多数 glob 实现相反），用户难以凭直觉正确使用。
2. **"恰好一级后代"是 `**` 给不了的粒度**——`**` 要么不含后代、要么全部后代，没有"只下一层"。要表达"self + 恰好一级子"，用户必须手写 `["order", "order.*"]` 两项，且需要知道 `*` 不含自身。

## 决策

在 `WatchListenerOptions` 上新增可选字段 `depth?: number`（默认 `0`），让用户以声明式深度钻取后代变更。`depth` 是**三档语义**，而非连续深度：

| depth | 订阅集（以 `order` 为例） | 触发范围 |
|---|---|---|
| `0`（默认） | `["order"]` | 仅 `order` 自身被重新赋值 |
| `1` | `["order", "order.*"]` | 自身 + 恰好一级后代 |
| `≥ 2` | `["order.**"]` | `order` 自身 + 全部后代 |

多 paths 时对每个 path 各自展开后并集（如 `["order","user"]` + `depth:1` → `["order","order.*","user","user.*"]`）。

**关键事实（fastevent 2.2.1 运行时已核实）：**

- `**` **含自身**：`order.**` 会匹配 `order`、`order.x`、`order.x.y.z`。因此 `depth≥2` 退化为单条订阅，无需重复订 `order`。
- `*` **只匹配恰好一段**：故 `depth:1` 必须显式补 `order`，否则漏掉自身。
- `**` 只能出现在路径末尾。

## 理由

`depth` 定位为**自文档化的便利字段**：用户无需理解 `**` 含自身、`*` 不含自身这些反直觉细节，传 `depth: 1` 即得到"只下一层"、传 `depth: 2`（或更大）即得到"全部后代"。三档而非连续深度，是为了与 fastevent 通配符能力对齐——`*`/`**` 本就只有"一层"与"任意层"两档，`depth` 如实映射，不引入无法落地的"恰好 N 层"承诺。

## 备选方案

- **只做 `depth: 1`，"全部后代"交给文档鼓励用户写 `order.**`**（即 API 退化为布尔 `shallow?: true` ≡ self + 一级子）：最小化新增面积，但要求用户懂 `**` 含自身，违背"自文档化"目标。否决。
- **真做成连续深度**（`depth: N` 展开到第 N 层 `order.*...*`）：功能最强，但性能随深度膨胀，且超出 fastevent 通配符的天然表达力，实现复杂。否决。
- **不新增，只教用户用通配符**：YAGNI 极致，但 `depth:1` 的精确一级能力无论如何都得让用户手写两项字符串，API 价值为负。否决。

## 后果

- **`depth` 实为三档**：`0` / `1` / `≥2`。`depth: 3` **不是**"三层深"，等价于 `depth: 2`（全部后代）。**需要精确多层（如恰好两层、恰好三层）请直接用 `**` 通配符手写。** 此限制须在 JSDoc 中写明。
- **回调 `operate.path` 传真实后代路径**：`depth > 0` 时，回调可能收到 `["order","price"]` 等后代路径，而非被监听的 `["order"]`。监听者据此判断"到底是哪个后代变了"。
- **不为 depth 派生事件新增或复用任何标记字段**（不复用 `broadcast`，不加 `derived`）：depth 派生事件如实报告"发生了什么路径的变更"，不存在重复消解需求。
- **`once: true` 时 `depth` 无效**，静默降级为 `depth: 0`：因为 fastevent 的 `once` 语义无法在"depth 展开出的多条订阅"上正确聚合（首次任意触发即整体解绑需要自定义聚合 off，代价超出收益），故一旦指定 `once`，depth 被忽略。
- **watchAll 模式（`watch(cb)` / `watch("*")` / `watch("**")` / 空数组）下传 `depth` 静默忽略**：该模式已由 `onAny` 全覆盖，depth 无意义。
- **数组元素变动纳入 depth 回调**：`order.items.*` 会捕获数字索引段（`order.items.0` 等），不另设规则。
- **重复订阅不去重通配符覆盖**：depth 展开仅做字面去重（同一 path 字符串合并）；若展开后的订阅集与用户显式 paths 存在通配符覆盖关系（如 `order.*` 覆盖 `order.price`），同一变更可能触发回调多次。需要严格单次触发请避免 depth 与显式后代路径混用。
