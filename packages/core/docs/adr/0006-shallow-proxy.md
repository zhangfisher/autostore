# `shallow()`：值级标记的一层浅代理

## 背景

状态树的所有嵌套对象都会被深度代理，以支撑细粒度的路径订阅与依赖收集。但对大型数组/大对象（上万条记录的列表、批量数据缓存）而言，深度代理的创建与遍历成本成为数量级瓶颈。

实测数据（Bun/Windows，10k 对象数组逐元素读属性）：

- 原生对象直读：约 **0.05ms**
- AutoStore 深代理读取：约 **35ms**

即 Proxy 陷阱的固定开销占读取热路径的 **99% 以上**。此前尝试的代理内部微优化（订阅门控、路径预拼接、专用陷阱等）收益仅 -5~8%（天花板已被实测钉死）；共享 handler 架构（Vue 风格）因本库每个代理必须携带路径上下文，实测净负收益（读取回退 26~50%）已被否决。结论：数量级收益只能来自**让热路径根本不进陷阱**。

## 决策

新增值级标记 API `shallow(obj)`：对象被标记后进入状态树时**仅创建一层浅代理**。

- **顶层代理保留完整语义**：get 陷阱照常产生事件（依赖收集可用）、set/delete 照常通知、数组方法劫持（insert/remove/update）完整保留、函数值照常创建计算属性 observer——即"只改代理深度，其余一切照旧"。
- **唯一差异**：get 返回的属性值不再递归创建代理，读出即为原始引用；直接修改该引用内部不产生任何事件。
- **标记只作用于被标记对象**：其所在父路径、兄弟路径完全不受影响。
- **标记载体为 `Symbol.for("__AS_SHALLOW_PROXY__")`**：Symbol 键不被 `Object.keys`/`for...in`/`JSON.stringify` 枚举，零序列化污染；`Symbol.for` 全局注册使跨捆绑副本（IIFE 场景）仍可判别。
- 配套导出 `isShallow()` 判别函数；标记幂等，`null`/标量输入安全原样返回。
- 代理深度语义由此三分：**深代理（默认）/ 浅代理（shallow）/ 不代理（markRaw）**。

## 理由

- **值级标记而非路径声明**（如 `new AutoStore(state, { shallow: ["items"] })`）：标记跟随数据走，嵌套任意深度内均生效，且实现只需在 `createProxy` 的 `isRaw` 检查同点位增加一个分支（KISS）。
- **保留顶层全部事件语义**：shallow 数组的核心价值是"行级数据 bulk、增删改仍可订阅"。若连事件一起砍掉（纯性能特区），`watch`/`collectDependencies` 将失效，语义断裂面过大。实测深层递归代理占成本 90%+，保留单层事件不构成瓶颈。
- **Symbol 而非字符串 flag**：shallow 的目标场景（大对象）恰好是高频进快照/同步的数据，`markRaw` 现有字符串 flag 会泄漏进 `JSON.stringify`（实测 `{"a":1,"__AS_SKIP_PROXY__":true}`），Symbol 从根源消除。代价是对象经序列化传输后标记丢失、对端恢复深代理——属性能退化而非语义错误，方向安全。

## 备选方案

- **路径声明式**（store 选项声明 shallow 路径列表）：对"数据来自远端、标记应跟着数据走"的场景不友好，且需要通配路径匹配器。否决。
- **字符串 flag（沿用 markRaw 模式）**：跨序列化保留标记，但污染快照与同步载荷，需在每个序列化点做过滤（治标）。否决。
- **WeakSet 注册表**：不污染序列化，但标记不随对象克隆/传输，且与 markRaw 的 flag 机制分叉。否决。
- **`markRaw` 顺带迁移到 Symbol**：属存量行为变更，影响面超出本决策，另行处理。

## 后果

- **读出即裸是本 API 的本质取舍**：从浅对象读出的嵌套对象，直接修改其内部静默无事件；React 订阅浅对象内部路径（`$('items.0.name')`）永不触发。须订阅被标记路径本身。文档（`docs/zh/store/guide/store/shallow.md`）已显性标注。
- **浅对象内整体替换结构化属性会触发子树广播**（ADR-0001），派生后代操作的行为与深代理一致；但 `watchAll`（`onAny`）订阅者不接收广播派生事件（其无具体路径，不满足"已订阅后代"判定）。
- **浅对象内函数值仍会创建计算属性 observer 并回写**，语义与深代理一致，无特判。
- **`markRaw` 的字符串 flag 序列化泄漏为存量行为**，本次不治。
- **类型层对齐**：`ComputedState` 顶部新增 `ShallowObject` 短路分支（置于数组分支之前），分发到新工具类型 `ShallowState<T>`——对成员做**单层**转换（函数成员 → `PickComputedResult`，其余原样保留、不递归），与浅代理"直接成员照常处理、不再递归"的运行时语义严格一致。浅对象内的计算属性函数在类型上映射为计算结果类型，而非停留在函数类型。短路置于顶层一处即可覆盖属性值/数组元素等所有递归入口（递归均经 `ComputedState` 自身）。对齐 `RawObject`（markRaw）的既有短路先例，但规避其被数组分支抢先的隐患。
- 性能验证设施：`packages/core/bench/reactive-bench.ts`（`bun run bench`），含基线存档。
